# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the app

```bash
pip install -r requirements.txt
python app.py
```

The app runs at `http://localhost:5001` in debug mode.

## Architecture

**Flask backend (`app.py`)** — thin routing layer. All business logic lives in `data_processor.py`.

**Data layer (`data_processor.py`)** — two cached module-level DataFrames, both lazily loaded on first access. The CSV path resolves through `get_active_dataset()` against the `DATASETS` registry — see "Datasets" below.
- `_df` (via `load_data()`) — "spending only" frame used by every existing tab. Filters to `type == "regular"`, `excluded != true`, `status != "planned"`, `amount > 0`.
- `_df_full` (via `load_full_data()`) — frame used by the Overview budget viz. Includes both `type == "regular"` (with the same `excluded` filter) and `type == "income"` rows. Income rows in Copilot's export are flagged `excluded=true` by convention, so the `excluded` filter is intentionally NOT applied to income rows. Income amounts are stored as positive values in the `pos_amount` column. Internal-transfer rows are excluded.

`set_active_dataset(key)` clears both DataFrame caches and the cached active key — the next API call lazy-rehydrates from the new CSV. The frontend dropdown follows up with a full page reload, so all in-memory frontend state resets at the same time.

Category normalization (applied to both frames): uses `category` if present, falls back to `parent category`, then `"Uncategorized"` — stored as `category_norm`. The CSV's `parent category` column is also surfaced via `category_meta()` (one row per `category_norm`, with the most common parent for that leaf or `None` for orphans). The frontend joins on `category_norm` to inherit colors from parent groups.

**API endpoints** (`/api/summary`, `/api/monthly`, `/api/categories`, `/api/transactions`, `/api/radial`, `/api/categories/list`, `/api/category-meta`, `/api/category-hierarchy`, `/api/months/list`, `/api/top-categories`, `/api/category-detail`, `/api/overview/snapshot`, `/api/overview/budget`, `/api/overview/budget/months`, `/api/datasets`, `/api/datasets/active`) — all return JSON consumed by the frontend. `/api/radial` returns `{year_str: [jan..dec]}` (12 floats per year) and accepts an optional `category=<leaf>` filter or `parent=<name>` filter (mirrors `/api/monthly`); `parent` wins when both are passed. Powers the Habits-tab radial chart (year-over-year monthly spend; one ring per year). `/api/transactions` supports server-side filtering and pagination (50 rows/page) plus optional `start_day` / `end_day` day-range params used by the Overview tab's "this time last month" linkout, and a `parent` filter that scopes by parent group (used for cross-tab nav from a parent-scope drill-down). `/api/monthly` accepts `categories`, `start`, `end`, `granularity` (`day` | `week` | `month`), plus `parent` and `group_by`: when `group_by=parent`, the response shape becomes `[{period, totals: {key: amount}}]` with parent groups as keys (orphans rolled into `"Other"`); when `parent=<name>` is also passed, keys become that parent's child leaves instead. `/api/summary` accepts `level` (`all` | `parent` | `leaf`) and `category` to scope KPI values to the active selection, plus `year_month` (focused month, drives `this_month`/`last_month`/`top`) and optional `avg_start` / `avg_end` (YYYY-MM-DD) which bound the `monthly_avg` KPI to the chart's range. Response includes `monthly_avg` + `avg_months` (count of months averaged over) and a `top` block (`{label, level, value}`) where `top.level` flips between `parent` / `leaf` / `merchant` so the frontend eyebrow can read "Top Category" / "Top Child" / "Top Merchant". `/api/category-detail` accepts `level` (`all` | `parent` | `leaf`); `level=parent` aggregates across all leaves under the parent and adds a `by_child` breakdown, `level=all` ignores `category` and adds `by_parent`. `/api/category-hierarchy?year_month=YYYY-MM` returns the tree `{month, all_total, nodes: [{name, level, total, children}]}` used to render the Habits-tab category rail; orphan leaves sit at the top level alongside parent groups, all sorted by total spend descending. `/api/category-meta` returns `[{category, parent}]` — used by the frontend color system so children of parent groups inherit the parent's hue. `/api/overview/snapshot?month=YYYY-MM` returns the four-card snapshot for the Overview tab. `/api/overview/budget?month=YYYY-MM` returns income items + top-N spending categories for the bars on the Overview budget viz. `/api/datasets` returns `[{key, label, active}]` for the header switcher; `POST /api/datasets/active` with `{"key": "..."}` swaps the active dataset (clears caches), 400s on unknown keys.

**Frontend (`static/js/app.js`)** — vanilla JS, no build step. Three top-level tabs managed by `showTab()`:
- `overview` — the default landing tab. Four equal-weight cards plus a cumulative line chart. State in `overviewSnapshot`; init via `initOverviewTab()`. Lazy-initialized on first activation.
- `habits` — KPI strip + chart card (with its own range picker, bar↔radial chart-type toggle, and Total↔Stacked toggle) + always-rendered drill-down (with a focused-month chip in its header). The chart card has two interchangeable trend visualizations gated by `chartType` (`'bar' | 'radial'`, default `'bar'`, in-tab session memory only — a hard reload resets to bar). The bar↔radial icon toggle (`#habits-charttype-toggle`) is desktop-only (`hidden md:inline-flex`); on viewports below 768px the chart auto-falls back to bar via a `matchMedia` listener. Radial mode swaps the timeframe pill for a year multi-select (`#radial-year-dropdown`); the Total↔Stacked toggle is hidden in radial mode. Year colors map by recency to `--color-radial-0..5` (most-recent year → palette index 0). Years selected in the picker that have zero spending in the active scope render no ring (silently dropped); when the resulting selection is empty, the chart shows a "No data for [scope] in selected years" overlay. The radial trace dispatcher is `renderHabitsTrend()` — every Habits setter calls it; it forwards to `renderHabitsChart()` (bar) or `renderHabitsRadial()` (radial) based on `chartType`. Radial state: `chartType`, `radialYears: Set<string>`, `_radialDataCache` (scope-keyed cache). Scope navigation lives in the **page-header chip**: the secondary nav reads "Your Habits for [📊 All Spending]"; clicking the chip opens `#hc-chip-panel`, a dropdown rendered by `renderCategoryTree()` (fed by `/api/category-hierarchy`) into `#hc-cat-panel-list`. Clicking "All Spending" / a parent / a leaf in the dropdown calls `setScopeAll()` / `setScopeParent(name)` / `setScopeLeaf(name)`, atomically re-rendering KPIs + chart + drill-down + the chip itself (emoji + colored underline via `--cat-fg` CSS var). The right-rail tree was removed; the dropdown is the sole scope nav. Lens state splits into two independent dimensions: **`lensTimeframe`** is a quick-range preset (`last-3-months` / `last-6-months` / `last-12-months` / `ytd` / `all-time`) and drives the trend chart only — the chart always renders monthly bars. **`lensMonth`** is the focused YYYY-MM and drives the KPI strip + drill-down only. Changing `lensTimeframe` resets `lensMonth` to the most-recent month in the new range; clicking a chart bar sets `lensMonth` and smooth-scrolls to the drill-down (the chart itself does **not** re-render). The drill-down's month chip (`buildDrillDownMonthPanel`) lets the user change `lensMonth` directly without going back to the chart. The KPI Avg follows `lensTimeframe` (`/api/summary` accepts `avg_start` / `avg_end`) so it scales with the chart range; its eyebrow label flips between "3-Mo Avg", "12-Mo Avg", "YTD Avg", etc. via `KPI_AVG_LABEL`. Other lens state: `lensLevel` (`'all' | 'parent' | 'leaf'`), `lensCategory`, `lensChartView` (`'total' | 'stacked'`, only meaningful at scope=all; auto-flips with scope). `lensCompare` is dormant (UI removed). Drill-down pie has a Proportion/Composition toggle at parent scope (defaults to Proportion; resets on every scope change; Composition is disabled when the parent has ≤1 child with spend in the focused month). Leaf scope is Proportion only; "all" scope is Composition only. Toggle re-renders from a cached `_ddLastData` payload — no `/api/category-detail` re-fetch on mode flip. Initialized lazily on first tab activation via `initDashboard()`. Stacked-child colors (chart) and parent-composition-pie shades are derived from the parent's hue via `derivedShade()` (HSL lightness ramp where darker = higher spend, lighter = lower spend).
- `transactions` — filterable transaction table. Reads `window.moneyHabitsNav` on activation to apply pre-set filters from Overview-tab linkouts.

Cross-tab navigation uses `window.moneyHabitsNav` — source tab sets it, destination tab reads it on activation. See §4.3 of `DESIGN-SYSTEM.md`.

**Category render helpers** (always use these — never hand-compose color classes or emoji):
- `catSlug(cat)` → returns the slug ('food' | 'personal' | 'car' | 'shopping' | one of 19 orphan slugs | 'default'). Children resolve to their parent slug via `_catMeta` (hydrated by `loadCategoryMeta()` from `/api/category-meta`).
- `catChipStyle(cat)` → inline style string with `background-color:var(--color-cat-{slug}-bg);color:var(--color-cat-{slug}-fg);`. Used wherever a category needs a colored chip or soft-bg circle.
- `catHex(cat, shade)` → resolved hex via `token()` for Plotly traces. Default shade is `mid` (~Tailwind 500).
- `catEmoji(cat)` / `catLabelHtml(cat)` → leaf-identity emoji (32 unique). Wrap with `<span class="cat-emoji">` so the OS color-emoji font wins.

Color tokens for these live in `static/css/style.css :root` as `--color-cat-{slug}-{bg|fg|mid}`. To add a new category color, add the three CSS vars and the slug; never extend `tailwind.config.js` colors for category use. Full design rationale in `DESIGN-SYSTEM.md` §1.4–1.5 and §2.6–2.7.

Charts use Plotly.js (CDN). Plotly trace colors come from CSS custom properties on `:root` via the `token()` helper — never hardcoded hex. **Tooltips are custom DOM**, not Plotly's native hoverlabel — every trace sets `hoverinfo: 'none'` and the chart's `plotly_hover` / `plotly_unhover` events drive a single shared `#ct-tip` element. Per-chart content builders live in `app.js` named `tip*HTML` (`tipBarHTML`, `tipPieHTML`, `tipCumulHTML`, `tipBubbleHTML`, `tipOverviewCumulHTML`, `tipRadialHTML`); they share the `tipCard()` primitive (rounded card, optional `data-accent` left border bound to `--color-cat-{slug}-mid`, Inter font, soft shadow). Each render function calls `hideCustomTooltip()` at the top so re-renders don't leave a stale tooltip.

**Templates** — Jinja2 with `base.html` / `index.html`. Tailwind CSS is pre-built — `static/css/tailwind.css` is the compiled output of `tailwind.input.css`. Rebuild with `npx -y tailwindcss@3.4.19 -i tailwind.input.css -o static/css/tailwind.css --minify` after introducing any new utility class. Custom accent color palette: `accent-{50,100,200,500,600,700}` maps to indigo (see `tailwind.config.js`). A secondary sticky nav below the top nav carries the active tab's page header — large title (`#page-title`) plus supporting subtitle (`#page-subtitle`). Each tab's render path drives it via `setPageHeader(title, subtitle)` for plain-text titles, or by overriding `#page-title.innerHTML` directly when the title needs an inline interactive element. Overview's `renderOverviewHeader()` injects an "Overview" eyebrow + "Your Spending Snapshot for [Month YYYY]" where the month is an `#ov-month-btn` button opening a `#ov-month-panel` dropdown of all dataset months — picking a month calls `setOverviewMonth(month)` which re-fetches snapshot + top-cats and re-renders all four cards + the cumulative chart via `loadAndRenderOverview(month)`. Transactions' `renderTransactionsHeader()` posts "Transactions" + filter summary from `transactionsSubtitle()`. Habits' `setHabitsPageHeader()` posts the active scope tail (chip + sibling `.hc-chip-bar` pill underline whose color is bound to the active scope's data-viz mid token) and is called from every Habits setter (`setLensScope`, `setLensTimeframe`, `setLensMonth`) plus `initDashboard`. The page-title brand wordmark in the top nav (`#brand-home-btn`) is a button that returns to the Overview tab from anywhere. The previously in-content `#overview-header` and `#transactions-header` divs are gone — the secondary nav owns page titling.

## Design system

All design decisions — typography scale, color tokens, component patterns, layout rules, and anti-patterns — live in [`DESIGN-SYSTEM.md`](./DESIGN-SYSTEM.md). Read it before building or modifying any UI surface.

The app must always be fully responsive at mobile, tablet, and desktop widths. Use Tailwind responsive prefixes (`md:`, `lg:`) per `DESIGN-SYSTEM.md` §5.3. Plotly charts must use `responsive: true` in their config.

## Datasets

The app ships two persona datasets and a header dropdown that swaps between them.

- **Registry**: `DATASETS` in `data_processor.py` maps `key → {label, path}`. Add new personas by appending entries here (and dropping the CSV at the matching path) — no other code changes required.
- **Files**: `datasets/student.csv` (NYC Student) and `datasets/young-pro.csv` (NYC Young Professional). Both are gitignored by default since they may contain personal-export data; remove the `datasets/*.csv` line in `.gitignore` before committing synthetic personas to a public repo.
- **Active selection**: persisted in `.active-dataset` (gitignored, lazily created at the project root). Defaults to `student` when missing or invalid. Read via `get_active_dataset()`, written via `set_active_dataset(key)`.
- **UI**: top-right of the header (`templates/base.html`), wired by `initDatasetSwitcher()` in `static/js/app.js`. Selection triggers `POST /api/datasets/active` followed by a full page reload — this is the simplest reset path across the lazy DataFrame caches and all frontend state (Overview snapshot, lens state, transactions filters, etc.).

## CSV format

Expected columns: `date`, `name`, `amount`, `status`, `category`, `parent category`, `excluded`, `tags`, `type`, `account`, `account mask`, `note`, `recurring`. The CSVs are exported from a personal finance tool (Copilot).

Conventions:
- `type` ∈ `{regular, income, internal transfer}`. Only `regular` is used for historical spending views; `income` is used by the Overview budget bars.
- Copilot flags every `income` and `internal transfer` row with `excluded=true`. The `_df_full` loader bypasses the `excluded` filter for income rows to compensate.
- Income rows have **negative `amount`** values (Copilot convention — money in is a negative cashflow). The data layer takes `abs(amount)` (`pos_amount`) before display.
- `status` ∈ `{posted, pending, planned}`. The CSV today contains only `posted`/`pending`; `planned` is reserved for forward-looking rows. Both `_df` (historical spending) and the `paid`-side of the budget viz exclude `planned` rows.

To refresh data, overwrite the CSV in `datasets/` for the relevant persona — restart the server (or hit `/api/datasets/active` with the same key) to pick up the new file. The dropdown switch already clears the cache; a plain file overwrite without a switch needs a restart.
