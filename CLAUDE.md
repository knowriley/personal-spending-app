## Running the app

```bash
pip install -r requirements.txt
python app.py
```

The app runs at `http://localhost:5001` in debug mode.

## Architecture

**Flask backend (`app.py`)** — thin routing layer. All business logic lives in `data_processor.py`.

**Data layer (`data_processor.py`)** — two cached module-level DataFrames, both lazily loaded on first access. The CSV path resolves through `get_active_dataset()` against the `DATASETS` registry — see "Datasets" below. A full walkthrough of the CSV → frame pipeline (filters, derived columns, per-request derivations) lives in [`DATA-PIPELINE.md`](./DATA-PIPELINE.md).
- `_df` (via `load_data()`) — "spending only" frame used by every existing tab. Filters to `type == "regular"`, `excluded != true`, `status != "planned"`, `amount > 0`.
- `_df_full` (via `load_full_data()`) — **reserved for future use**: frame intended for an Overview income-vs-spending viz. Currently dormant — no frontend code calls the endpoints that read it. Includes both `type == "regular"` (with the same `excluded` filter) and `type == "income"` rows. Income rows in Copilot's export are flagged `excluded=true` by convention, so the `excluded` filter is intentionally NOT applied to income rows. Income amounts are stored as positive values in the `pos_amount` column. Internal-transfer rows are excluded.

`set_active_dataset(key)` clears both DataFrame caches and the cached active key — the next API call lazy-rehydrates from the new CSV. The Settings-sheet persona switcher follows up with a full page reload, so all in-memory frontend state resets at the same time.

Category normalization (applied to both frames): uses `category` if present, falls back to `parent category`, then `"Uncategorized"` — stored as `category_norm`. The CSV's `parent category` column is also surfaced via `category_meta()` (one row per `category_norm`, with the most common parent for that leaf or `None` for orphans). The frontend joins on `category_norm` to inherit colors from parent groups.

**API endpoints** (`/api/summary`, `/api/monthly`, `/api/categories`, `/api/transactions`, `/api/radial`, `/api/categories/list`, `/api/category-meta`, `/api/category-hierarchy`, `/api/months/list`, `/api/top-categories`, `/api/category-detail`, `/api/overview/snapshot`, `/api/overview/budget`, `/api/overview/budget/months`, `/api/datasets`, `/api/datasets/active`) — all return JSON. Most are consumed by the frontend; the two `/api/overview/budget*` routes are reserved for future use (see below). `/api/radial` returns `{year_str: [jan..dec]}` (12 floats per year) and accepts an optional `category=<leaf>` filter or `parent=<name>` filter (mirrors `/api/monthly`); `parent` wins when both are passed. Powers the Habits-tab radial chart (year-over-year monthly spend; one ring per year). `/api/transactions` supports server-side filtering and pagination (50 rows/page) plus optional `start_day` / `end_day` day-range params used by the Overview tab's "this time last month" linkout, and a `parent` filter that scopes by parent group (used for cross-tab nav from a parent-scope drill-down). `/api/monthly` accepts `categories`, `start`, `end`, `granularity` (`day` | `week` | `month`), plus `parent` and `group_by`: when `group_by=parent`, the response shape becomes `[{period, totals: {key: amount}}]` with parent groups as keys (orphans rolled into `"Other"`); when `parent=<name>` is also passed, keys become that parent's child leaves instead. `/api/summary` accepts `level` (`all` | `parent` | `leaf`) and `category` to scope KPI values to the active selection, plus `year_month` (focused month, drives `this_month`/`last_month`/`top`) and optional `avg_start` / `avg_end` (YYYY-MM-DD) which bound the `monthly_avg` KPI to the chart's range. Response includes `monthly_avg` + `avg_months` (count of months averaged over) and a `top` block (`{label, level, value}`) where `top.level` flips between `parent` / `leaf` / `merchant` so the frontend eyebrow can read "Top Category" / "Top Child" / "Top Merchant". `/api/category-detail` accepts `level` (`all` | `parent` | `leaf`); `level=parent` aggregates across all leaves under the parent and adds a `by_child` breakdown, `level=all` ignores `category` and adds `by_parent`. `/api/category-hierarchy?year_month=YYYY-MM` returns the tree `{month, all_total, nodes: [{name, level, total, children}]}` used to render the Habits-tab category rail; orphan leaves sit at the top level alongside parent groups, all sorted by total spend descending. `/api/category-meta` returns `[{category, parent}]` — used by the frontend color system so children of parent groups inherit the parent's hue. `/api/overview/snapshot?month=YYYY-MM` returns the four-card snapshot for the Overview tab. `/api/overview/budget?month=YYYY-MM` and `/api/overview/budget/months` are **reserved for future use** — they would return income items + top-N spending categories for an Overview income-vs-spending viz, but no frontend code currently calls them. `/api/datasets` returns `[{key, label, active}]` for the header switcher; `POST /api/datasets/active` with `{"key": "..."}` swaps the active dataset (clears caches), 400s on unknown keys.

**Frontend (`static/js/app.js`)** — vanilla JS, no build step. Three top-level tabs managed by `showTab()`:
- `overview` — the default landing tab. Four equal-weight cards plus a cumulative line chart. State in `overviewSnapshot`; init via `initOverviewTab()`. Lazy-initialized on first activation.
- `habits` — KPI strip + chart card (with its own range picker, bar↔radial chart-type toggle, and Total↔Stacked toggle) + always-rendered drill-down (with a focused-month chip in its header). The chart card has two interchangeable trend visualizations gated by `chartType` (`'bar' | 'radial'`, default `'bar'`, in-tab session memory only — a hard reload resets to bar). The bar↔radial icon toggle (`#habits-charttype-toggle`) is desktop-only (`hidden md:inline-flex`); on viewports below 768px the chart auto-falls back to bar via a `matchMedia` listener. Radial mode swaps the timeframe pill for a year multi-select (`#radial-year-dropdown`); the Total↔Stacked toggle is hidden in radial mode. Year colors are derived from the active scope's hue by recency via `radialColorFor()` → `derivedShade(scopeColor, idx, count)` (most-recent year → index 0 → darkest), so the rings inherit the scope's identity color rather than a separate palette. Years selected in the picker that have zero spending in the active scope render no ring (silently dropped); when the resulting selection is empty, the chart shows a "No data for [scope] in selected years" overlay. The radial trace dispatcher is `renderHabitsTrend()` — every Habits setter calls it; it forwards to `renderHabitsChart()` (bar) or `renderHabitsRadial()` (radial) based on `chartType`. Radial state: `chartType`, `radialYears: Set<string>`, `_radialDataCache` (scope-keyed cache). Scope navigation lives in the **page-header chip**: the secondary nav reads "Your Habits for [📊 All Spending]"; clicking the chip opens `#hc-chip-panel`, a dropdown rendered by `renderCategoryTree()` (fed by `/api/category-hierarchy`) into `#hc-cat-panel-list`. Clicking "All Spending" / a parent / a leaf in the dropdown calls `setScopeAll()` / `setScopeParent(name)` / `setScopeLeaf(name)`, atomically re-rendering KPIs + chart + drill-down + the chip itself (emoji + colored underline via `--cat-fg` CSS var). The right-rail tree was removed; the dropdown is the sole scope nav. Lens state splits into two independent dimensions: **`lensTimeframe`** is a quick-range preset (`last-3-months` / `last-6-months` / `last-12-months` / `ytd` / `all-time`) and drives the trend chart only — the chart always renders monthly bars. **`lensMonth`** is the focused YYYY-MM and drives the KPI strip + drill-down only. Changing `lensTimeframe` resets `lensMonth` to the most-recent month in the new range; clicking a chart bar sets `lensMonth` and smooth-scrolls to the drill-down (the chart itself does **not** re-render). The drill-down's month chip (`buildDrillDownMonthPanel`) lets the user change `lensMonth` directly without going back to the chart. The KPI Avg follows `lensTimeframe` (`/api/summary` accepts `avg_start` / `avg_end`) so it scales with the chart range; its eyebrow label flips between "3-Mo Avg", "12-Mo Avg", "YTD Avg", etc. via `KPI_AVG_LABEL`. Other lens state: `lensLevel` (`'all' | 'parent' | 'leaf'`), `lensCategory`, `lensChartView` (`'total' | 'stacked'`, only meaningful at scope=all; auto-flips with scope). `lensCompare` is dormant (UI removed). Drill-down pie has a Proportion/Composition toggle at parent scope (defaults to Proportion; resets on every scope change; Composition is disabled when the parent has ≤1 child with spend in the focused month). Leaf scope is Proportion only; "all" scope is Composition only. Toggle re-renders from a cached `_ddLastData` payload — no `/api/category-detail` re-fetch on mode flip. Initialized lazily on first tab activation via `initDashboard()`. Stacked-child colors (chart) and parent-composition-pie shades are derived from the parent's hue via `derivedShade()` (HSL lightness ramp where darker = higher spend, lighter = lower spend).
- `transactions` — filterable transaction table. Reads `window.moneyHabitsNav` on activation to apply pre-set filters from Overview-tab linkouts.

Cross-tab navigation uses `window.moneyHabitsNav` — source tab sets it, destination tab reads it on activation. See §4.3 of `DESIGN-SYSTEM.md`.

**Category render helpers** (always use these — never hand-compose color classes or emoji):
- `catSlug(cat)` → returns the slug. Resolution order: explicit `PARENT_SLUG` entry (covers both Copilot's `Car & Transport` and the synthetic dataset's `Transportation`, plus `Food & Drink`, `Personal Care`, `Shopping`, `Housing`, `Utilities`, `Health`, `Entertainment`, `Debt`, `Other`) → parent-group inheritance via `_catMeta` (hydrated by `loadCategoryMeta()` from `/api/category-meta`) → `ORPHAN_SLUG` for true orphan leaves → `'default'`. Parent inheritance wins over `ORPHAN_SLUG` so leaves visually cluster under their parent group even if the leaf name happens to overlap with a known orphan slug (e.g. `Rent` under `Housing`).
- `catChipStyle(cat)` → inline style string with `background-color:var(--color-cat-{slug}-bg);color:var(--color-cat-{slug}-fg);`. Used wherever a category needs a colored chip or soft-bg circle.
- `catHex(cat, shade)` → resolved hex via `token()` for chart datasets/traces. Default shade is `mid` (~Tailwind 500).
- `catEmoji(cat)` / `catLabelHtml(cat)` → leaf-identity emoji (32 unique). Wrap with `<span class="cat-emoji">` so the OS color-emoji font wins.

Color tokens for these live in `static/css/style.css :root` as `--color-cat-{slug}-{bg|fg|mid}`. To add a new category color, add the three CSS vars and the slug; never extend `tailwind.config.js` colors for category use. Full design rationale in `DESIGN-SYSTEM.md` §1.4–1.5 and §2.6–2.7.

Charts use **Chart.js 4.x** (vendored locally at `static/js/chart.umd.min.js`, plus `chartjs-plugin-datalabels.min.js` for the drill-down donut's slice labels) for every chart **except the Habits radial**, which is a **hand-rolled SVG** in `static/js/radial.js` (no chart library). There is no Plotly in v2 — it was fully removed in M9. Chart colors come from CSS custom properties on `:root` via the `token()` helper — never hardcoded hex. Shared Chart.js infra in `app.js`: `initChartDefaults()` (global `Chart.defaults` per PRD §8.1, run lazily at first mount), `chartLayout()` (per-render mobile/desktop padding + scale fragment, spread into each chart's options), `getChartCanvas(id)` (find-or-create the canvas inside the old `<div>` container), and `mountChart(id, config)` / `destroyChart(id)` (a `_charts` registry that destroys the prior instance before re-creating — call `destroyChart` before any `innerHTML` reset of a chart container to avoid a detached-canvas resize-observer leak). The converted render fns: `renderOverviewLineChart` (line), `renderHabitsChart` (bar; stacked modes show a legend with `legend.onClick` drill, single modes don't; `applyMonthHighlight` dims non-focused bars via per-bar `backgroundColor` alpha + `chart.update('none')`), `renderDdPie` (doughnut; datalabels on in composition modes), `renderDdCumulative` (line), `renderDdBubble` (bubble, desktop; keeps the v1 `stackPositions` pixel math and feeds Chart.js x/y/r) and `renderDdDailyStrip` (the mobile-only daily-totals bar strip that replaces the bubble below 768px — derived by first-differencing `cumulative_spend`; the `matchMedia` listener swaps them on breakpoint cross). The **SVG radial** (`radial.js`) exposes `window.MoneyHabitsRadial.render(container, opts)` / `setHighlight(container, year)` / `destroy(container)`; it's a pure view + hit-test layer (renders rings, 12 month spokes, faint reference rings, clickable node dots, a color-swatch year legend) and emits `onMonthHover` / `onMonthClick` / `onYearClick` while `renderHabitsRadial` in `app.js` keeps owning state (selected years, the click-pinned year via `radialHighlightYear`, the focused month) and the tooltip. Radial is desktop-only; `matchMedia` falls back to bar below 768px. **Chart.js tooltips are native**, styled to match the card look: `makeTipExternal(buildSpec)` returns an `external` handler that renders the shared `tipCard()` markup (rounded card, optional `data-accent` left border bound to `--color-cat-{slug}-mid`) into the `#cjs-tip` element; per-chart spec builders are named `cjsTip*` (`cjsTipBar`, `cjsTipPie`, `cjsTipCumul`, `cjsTipBubble`, `cjsTipOverviewCumul`). Habits bars suppress the tooltip on mobile (tap drills instead). The **mouse-event custom-DOM tooltip** (`#ct-tip`, `showCustomTooltip`, `positionCustomTooltip`, `hideCustomTooltip`, `tipRadialHTML`) is used by the SVG radial; the other `tip*HTML` builders are kept but dormant. Each render fn still calls `hideCustomTooltip()` at the top defensively.

**Templates** — Jinja2 with `base.html` / `index.html`. Tailwind CSS is pre-built — `static/css/tailwind.css` is the compiled output of `tailwind.input.css`. Rebuild with `npx -y tailwindcss@3.4.19 -i tailwind.input.css -o static/css/tailwind.css --minify` after introducing any new utility class. Custom accent color palette: `accent-{50,100,200,500,600,700}` maps to indigo (see `tailwind.config.js`).

**Navigation (M10)** — the v1 top tab bar is gone. Below 768px a fixed **bottom tab bar** (`#bottom-nav`, stacked icon+label); at ≥768px a fixed **left side rail** (`#side-rail`, 240pt / `w-60`, content offset via `md:flex` on `<body>`) with **inline icon+label rows**. Both hold the same three `[data-tab]` buttons (Overview / Habits / Transactions) styled by `.nav-btn`/`.rail-btn`/`.bottom-btn` in `style.css` — one SVG per button, outline when inactive and filled (`.is-active`) when active. A **Notion-style profile/dataset switcher** sits at the **top-left of the rail** (`#profile-btn`: initial badge + active-persona name + chevron) and as a compact **initial badge** in the mobile sticky header (`#profile-badge-mobile`); both open the shared `#profile-panel` dropdown (positioned near the trigger by `initProfileSwitcher()`), listing personas with a check on the active one. Selecting one POSTs `/api/datasets/active` + reloads. There is no gear / Settings entry yet — real Settings is deferred. `showTab(name, {updateHash})` drives section visibility + nav active state + the sticky title, and keeps the URL hash in sync (`#overview`/`#habits`/`#transactions`); a `popstate` listener restores tabs on back/forward, and boot reads `tabFromHash()`.

**Page headers** use the large-title pattern. A single shared **large-title block** (`#large-title-block`, holding `#page-title` + `#page-subtitle` + the Habits `#hc-chip-panel`) sits at the top of the `#app-scroll` container, repopulated per tab by the same renderers as before — `setPageHeader(title, subtitle)` for plain text, or `#page-title.innerHTML` for inline controls. Overview's `renderOverviewHeader()` injects an "Overview" eyebrow + "Your Spending Snapshot for [Month YYYY]" with an `#ov-month-btn` opening `#ov-month-panel` (→ `setOverviewMonth` → `loadAndRenderOverview`). Transactions' `renderTransactionsHeader()` posts "Transactions" + `transactionsSubtitle()`. Habits' `setHabitsPageHeader()` posts the scope chip + `.hc-chip-bar` underline. On **mobile** the large-title fades + shrinks into a sticky bar (`#sticky-header` / `#sticky-fade` + `#sticky-title`) over 60pt of scroll via `MoneyHabitsIOS.initLargeTitleScroll` (wired by `syncHeaderScroll()`, mobile-only, re-wired on the 768px breakpoint); on **desktop** the title is static (the rail is the persistent chrome). `ios.js` is loaded in `base.html` (it provides `openBottomSheet` + `initLargeTitleScroll`). The dormant `#txn-panel` aside is kept but `hidden`.

## Design system

All design decisions — typography scale, color tokens, component patterns, layout rules, and anti-patterns — live in [`DESIGN-SYSTEM.md`](./DESIGN-SYSTEM.md). Read it before building or modifying any UI surface.

The app must always be fully responsive at mobile, tablet, and desktop widths. Use Tailwind responsive prefixes (`md:`, `lg:`) per `DESIGN-SYSTEM.md` §5.3. Chart.js charts inherit `responsive: true` + `maintainAspectRatio: false` from `initChartDefaults()`, so their containers must carry a definite height (set per-viewport in the render fns); the SVG radial scales to its container via `viewBox` + `preserveAspectRatio`.

## Datasets

The app ships two persona datasets and a header dropdown that swaps between them.

- **Registry**: `DATASETS` in `data_processor.py` maps `key → {label, path}`. Add new personas by appending entries here (and dropping the CSV at the matching path) — no other code changes required.
- **Files**: `datasets/student.csv` (NYC Student) and `datasets/young-pro.csv` (NYC Young Professional). Both are gitignored by default since they may contain personal-export data; remove the `datasets/*.csv` line in `.gitignore` before committing synthetic personas to a public repo.
- **Active selection**: persisted in `.active-dataset` (gitignored, lazily created at the project root). Defaults to `student` when missing or invalid. Read via `get_active_dataset()`, written via `set_active_dataset(key)`.
- **UI**: the profile/dataset switcher, built by `initProfileSwitcher()` in `static/js/app.js` — the rail's `#profile-btn` (desktop) + `#profile-badge-mobile` (mobile) opening the shared `#profile-panel` dropdown. Selection triggers `POST /api/datasets/active` followed by a full page reload — this is the simplest reset path across the lazy DataFrame caches and all frontend state (Overview snapshot, lens state, transactions filters, etc.). A later task may swap the reload for an in-place re-render.

## CSV format

Expected columns: `date`, `name`, `amount`, `status`, `category`, `parent category`, `excluded`, `tags`, `type`, `account`, `account mask`, `note`, `recurring`. The CSVs are exported from a personal finance tool (Copilot).

Conventions:
- `type` ∈ `{regular, income, internal transfer}`. Only `regular` is used for historical spending views; `income` is loaded into `_df_full` for a future income-vs-spending viz (currently dormant — see `_df_full` note above).
- Copilot flags every `income` and `internal transfer` row with `excluded=true`. The `_df_full` loader bypasses the `excluded` filter for income rows to compensate.
- Income rows have **negative `amount`** values (Copilot convention — money in is a negative cashflow). The data layer takes `abs(amount)` (`pos_amount`) before display.
- `status` ∈ `{posted, pending, planned}`. The CSV today contains only `posted`/`pending`; `planned` is reserved for forward-looking rows. `_df` (historical spending) excludes `planned` rows, as does the `paid`-side of the dormant income-vs-spending viz.

To refresh data, overwrite the CSV in `datasets/` for the relevant persona — restart the server (or hit `/api/datasets/active` with the same key) to pick up the new file. The dropdown switch already clears the cache; a plain file overwrite without a switch needs a restart.
